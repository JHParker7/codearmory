Service keys (gatekeeperServiceKey, conductorForwardKey, hooksTriggerKey, etc.) are
auto-generated on first install and preserved across upgrades. No manual key generation
is required for a default installation.

IMPORTANT — fresh install only:
  Cross-service shared keys (gatekeeper-services, conductor-forward-key, hooks-trigger-key,
  registry service-accounts) are assembled by reading sibling secrets at render time. On a
  brand-new install those secrets do not yet exist, so the first install produces mismatched
  keys and services will fail to authenticate with each other. Fix this with a second apply:

    helm upgrade {{ .Release.Name }} <chart> -n {{ .Release.Namespace }}

  This is a one-time step. Subsequent upgrades sync correctly without it.

Before production use, make sure you have set:
  - gatekeeper.secret.oidcSigningKey              (stable ECDSA key; ephemeral if unset)
  - containers.secret.registryUrl                 (required for containers service)
  - giteaIntegration.secret.giteaUrl              (required when giteaIntegration.enabled)
  - giteaIntegration.secret.giteaAdminToken       (required when giteaIntegration.enabled)
  - postgresql.auth.postgresPassword              (optional — auto-generated when empty)
